앞 글 둘은 도구가 무엇인지였다. [Triton](/posts/2026-09-16-nvidia-triton/)은 학습이 끝난 모델을 HTTP·gRPC로 띄운다. [Langfuse](/posts/2026-09-16-langfuse/)는 LLM 호출의 프롬프트와 지연을 남긴다.

이 글은 **그 둘을 한 제품의 SaaS에 같이 둘 때** 무엇을 먼저 정하는가다. 특정 제품 이름을 쓰지 않는다. 운영에서 반복해서 깨진 자리만 적는다. 이 글을 쓰는 시점에 새 클라우드 GPU를 띄워 재지는 않았다.

끝까지 읽으면 넷이 된다.

1. GPU 추론과 LLM 문장 생성을 한 Triton 프로세스에 두지 않는 이유.
2. 앱 클러스터가 GPU 노드를 직접 갖지 않을 때 무엇이 빠지기 쉬운지.
3. 오토스케일보다 먼저 볼 것 — 카드 용량, 모듈 그룹, 동시 상한.
4. Langfuse를 앱 이미지와 분리하고, 고객 망에 사내 덤프를 복원하지 않는 이유.

## 목차

## 이 글에서 쓰는 말

- **정량 추론**: 입력(영상·신호)을 모델에 넣어 숫자와 구조화 결과를 받는 구간. GPU를 쓴다.
- **문장 생성**: 그 결과를 읽어 요약·결론 같은 텍스트를 만드는 구간. LLM을 부른다.
- **모듈 그룹**: Triton 모델 저장소에서 같이 켜고 끄는 묶음. 배포 프로파일이다.
- **원장**: 프로덕션에 무엇이 있는지를 적는 목록. 목록에 없으면 인프라 요청 자체가 안 생긴다.
- **시딩**: 빈 저장소에 프롬프트 같은 운영 자산만 API로 넣는 것. DB 통째 복원이 아니다.

## 1. 두 층으로 나눈다

한때는 문장 생성 모델도 Triton 모델 저장소에 있었다. gRPC로 같이 호출했다. 그 뒤 이 층을 **별도 HTTP 서비스**로 옮겼다.

옮긴 이유는 GPU 스케줄과 LLM 운영이 다르기 때문이다.

|         | 정량 추론 (Triton)               | 문장 생성 (HTTP)                   |
| ------- | -------------------------------- | ---------------------------------- |
| 자원    | GPU, 큰 이미지                   | CPU면 되는 경우가 많다             |
| 호출    | gRPC `ModelInfer`                | `POST /v1/...` 를 순서대로         |
| 상태    | 모델 가중치가 이미지 안          | DB·객체 저장소·프롬프트 레지스트리 |
| 관측    | Triton `/metrics`                | Langfuse 트레이스                  |
| 끄는 법 | 모듈 그룹을 저장소 밖으로 옮긴다 | 앱의 기능 토글                     |

공식 Triton은 모델 저장소의 폴더를 스캔한다. 꺼진 그룹을 다시 켜면 서버가 그 모델을 로드하려 한다. **호출자가 이미 HTTP로 바뀌었는데 옛 모델을 켜면**, 기동이 실패하거나 메모리만 먹고 아무도 안 부른다. 켜기 전에 호출 경로를 본다.

기능 토글은 둘이다.

1. 정량만 — GPU 추론만 연다.
2. 정량 + 정형화 + 문장 — HTTP 서비스가 살아 있어야 한다. 토글만 켜고 서버가 없으면 리포트 칸이 비거나 기본값 `localhost`를 찾아 조용히 실패한다.

앱 설정의 기본 주소가 `localhost`이면, 컨테이너 안에서 자기 자신을 찾는다. 외부 베이스 URL을 **명시**한다.

## 2. 앱 클러스터 밖에 둔다

많은 SaaS 앱은 Kubernetes에 올라가고, GPU 추론은 **다른 호스트의 host:port**다. 헬름 차트에 GPU 디플로이가 없을 수 있다. 그 공백은 실수가 아니라 "지금은 범위 밖"으로 적혀 있기도 하다.

그때 빠지는 것이 셋이다.

1. **원장에 GPU 행이 없다.** DB·큐·객체 저장소는 DR 목록에 있는데 추론만 없다. 없으면 질의 자체가 안 나간다.
2. **호출이 한 방향이 아니다.** 추론 서버가 분석 중에 앱 쪽에서 파일을 다시 받을 수 있다. 앱 → 추론만 열어 두고 반대가 막히면 한 건이 완결되지 않는다.
3. **엔드포인트가 정적 목록이다.** 부팅 때 host:port CSV를 한 번 읽는다. 오토스케일로 주소가 늘면 그 목록은 따라가지 않는다.

SaaS에 GPU를 편입한다는 결정은 "노드를 산다"가 아니다. **원장에 행을 만들고, 앱이 읽는 주소와 준비 검사와 메트릭 스크레이프를 같은 작업에서 고친다.**

## 3. 오토스케일보다 먼저 볼 것

클라우드에서 GPU를 돌린 선례가 있어도, 지금 모델 셋이 **그 카드에 들어가는지**는 다른 문제다. 24GB 카드에서 옛 프로파일이 돌아갔다고 해서, 지금 전체 모델을 같은 카드에 올리면 안 된다. 전체 로드가 24GB를 넘는 측정이 있으면 L4·A10G 급은 후보에서 뺀다.

모듈 그룹으로 프로파일을 나눈다.

- 납품·폐쇄망: 정량만. 문장 모델은 끈다.
- 개발·풀 파이프라인: 정량 + 정형화. 문장은 HTTP 쪽.
- 한 장의 VRAM에 스키마 두 벌을 동시에 올리지 못한다. 운영은 **하나만** 고른다.

동시 추론 상한 1은 설계 목표가 아니라, GPU 폭주 뒤에 들어온 안전장치인 경우가 있다. 상한이 환경변수로 열려 있으면, 코드 없이 값을 올리는 것이 1단계다. 엔드포인트를 여러 대로 늘리기 전에 한 대를 수직으로 연다.

오토스케일을 먼저 붙이면 바로 드러나는 구멍이 있다.

- 대기열이 화면에 없다. 사람은 멈춘 줄 안다.
- 판매한 제한 시간에 큐 우선순위가 없다.
- 용량 거절 한 번이 그 건을 영구 실패로 남긴다.
- 풀 안의 모델 버전이 서로 다른지 추적하지 못한다.

그래서 순서는 이것이다.

1. 카드 용량이 모델 프로파일보다 큰지.
2. 모듈 그룹이 그 프로파일과 맞는지.
3. 동시 상한 환경변수.
4. 준비 검사와 메트릭이 앱 헬스에 보이는지.
5. 그다음에야 풀과 서비스 디스커버리.

## 4. LLM 쪽은 이미지가 아니라 스택이다

문장 생성 HTTP는 GPU가 없을 수 있다. 대신 컨테이너가 여럿이다.

- 게이트웨이 한 포트. 고객용은 허용된 경로만 통과한다.
- 앱(추론 API).
- Langfuse 웹·워커·프록시.
- Postgres, ClickHouse, Redis, 객체 저장소.
- 백업과 지표를 도는 ops 컨테이너.

설계에서 반복되는 분리다. **앱 이미지를 새로 굽는 일이 Langfuse의 DB를 재시작하게 하지 않는다.** Fuse는 공식 이미지 스택으로 두고, 앱만 교체한다.

SaaS 패키지의 규칙.

1. 사내 Langfuse DB 덤프를 복원하지 않는다. 계정과 키가 같이 넘어온다. 빈 인스턴스를 초기화하고 프롬프트만 API로 넣는다.
2. `latest`를 쓰지 않는다. 태그 또는 digest로 고정한다.
3. 운영자 UI와 메트릭 포트를 인터넷에 열지 않는다. 기본은 루프백, 접근은 터널 또는 VPN.
4. 암호화 키를 기동 뒤에 바꾸지 않는다. 저장된 값을 못 읽는다.
5. 고객 환경의 Langfuse 화면에서 프롬프트 본문을 고치지 않는다. 다음 배포의 번들이 덮는다. 본문 정본은 사내에서 promote 한 뒤 export 한 파일이다.

저장소는 처음에 compose 안의 로컬 네 종으로 두고, 규모가 커지면 RDS·관리형 ClickHouse·ElastiCache·S3로 env만 바꾼다. 앱 컨테이너는 그대로다. 관리형으로 데이터를 옮길 때는 Postgres만 옮기면 프롬프트와 계정이 따라간다. superuser 덤프를 RDS에 그대로 넣지 않는다.

기동 완료 조건은 HTTP 200이 아니다. `/ready` 본문의 `ready`가 true이고 빠진 필수값이 빈 배열이어야 한다. 게이트웨이 `/healthz`는 프로세스 생존만 본다.

## 5. 관측을 두 갈래로 둔다

Triton 메트릭은 모델별 성공·실패·지연이다. GPU 사용량과 서버 처리량이다.

Langfuse 트레이스는 그 요청에 **어떤 프롬프트를 넣었는지**다. 문장 생성 경로에만 해당한다. 정량 gRPC 호출을 Langfuse에 넣으려 하지 않는다. 층이 다르다.

프롬프트 이름은 레지스트리 한곳이다. 추론 프로세스는 Langfuse에서 읽고, 실패하면 디스크 스냅샷으로 폴백한다. 코드에 프롬프트 본문을 두지 않는다.

## 6. 다음에 실습할 때

로컬에서 도구를 익히는 순서는 앞 글과 같다.

1. Triton 예제 저장소로 `/v2/health/ready`가 200인지.
2. Langfuse에 트레이스 한 건이 생기는지.

SaaS에 올리기 전에 종이로 채울 것은 이것이다.

1. GPU가 원장에 있는가.
2. 정량 프로파일이 그 카드에 들어가는가. 들어가는 숫자와 조건을 적는다.
3. 문장 서비스의 베이스 URL이 localhost가 아닌가.
4. 기능 토글과 실제 서버가 같이 켜지는가.
5. Langfuse UI가 공인망에 없는가.
6. 프롬프트 번들의 출처가 사내 production export인가.

재지 않은 처리량·비용을 적지 않는다. 선례의 건수와 시각은 그 프로파일·그 카드의 것이다.

## 여기서 하지 않은 것

- 특정 제품의 API 텐서 목록.
- Kubernetes GPU 오퍼레이터 설치 절차.
- 오토스케일 YAML.
- 클라우드 LLM으로 나가는 데이터의 법적 판단. 그건 운영 토글이 아니라 사람 결정이다.

오늘은 **층을 나누고, 원장에 올리고, 카드와 상한을 먼저 보는 것**까지다. 도구 이름은 Triton과 Langfuse이고, 배포 단위는 GPU 한 대와 HTTP 스택 한 벌이다.
